# Packet result / review handoff

- Packet and exact completed versus unfinished scope:
- Owner/model/effort; rework/escalation and observed usage only if available:
- Base and resulting source commit(s); branch/worktree clean/dirty:
- Concrete behavior/physics change and user consequence:
- Source/equation/input/runtime/artifact identities:
- Acceptance ID -> command/mechanism -> result -> evidence location:
- Failed attempts and unresolved blocked/not-applicable reasons:
- Synthetic/development/qualified-source/empirical evidence classifications:
- Before/after prediction/output/default consequences and limits:
- Independent review disposition/findings/corrections:
- What was not run/available and why; no implied old-machine artifacts:
- Current active processes/agents/resources and release of file leases:
- Exact next task and files/decisions/dependencies:
- Usage-limit failure/reset exact message/time if actually supplied:

COMPLETE means this bounded scope is reviewed and evidenced. It does not set a
physical/release gate PASS or silently close unfinished acceptance IDs.
