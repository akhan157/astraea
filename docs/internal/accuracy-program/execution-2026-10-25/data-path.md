# Data acquisition and qualification path

Research date: 2026-10-25. Planning source baseline: `761d6c3`. This is a research plan, not flight qualification or a change to the proposed acceptance specification. Companion: [candidateinventory.json](candidateinventory.json).

**Zero-cost public material can support a serious aerodynamic development and comparator program now. The inspected sources do not yet supply a qualified blind collegiate flight cohort.** There is a concrete public collegiate archive worth qualifying through a custodian; its metadata does not establish as-flown inputs, observation uncertainty or sufficient independent vehicles. A team-data dependency should therefore be a small, specified data package with named custody, rather than an indefinite request for “more flight data.”

No simulations, model changes, raw collegiate telemetry downloads, outreach, accounts or purchases were performed. Reserved round 2, Emerald and Vulcanite data were not opened. Existing public development-flight inputs were read only through their inventory, not fetched again.

## What was actually checked

Read the three accuracy-program reference/specification/exposure records and the existing external-input inventory. Read the cloud runtime/networking skill and local policy; environment status reported current enforced unrestricted HTTP access. Shell network requests used the inherited proxy and requested network capability. NASA coefficient PDFs were successfully downloaded to temporary storage and their method sections inspected. GitHub recursive **tree metadata**, repository documentation, two motor **input** files and a design LFS pointer were inspected. No repository was cloned wholesale; notebooks, HTML analyses, graphs, flight CSV/PF2 files and outcome-bearing spreadsheets were excluded.

The NASA catalog has a misleading secondary text string for D-4013 (“6.0 to 12.0”); the report itself says **0.60–1.20**. Use the PDF, not that catalog artifact. Some web fetches timed out; successful shell GET/HEAD checks below distinguish those failures from actual access barriers.

## Acquisition order that can be executed without opening new outcomes

1. **Coefficient packet first:** select D-4013 short/long zero-cant cases and matched D-4014 cases; acquire the verified PDFs, reconstruct fig. 1 exactly, transcribe conventions/corrections, then independently digitize chosen curves. Keep source PDF hash, printed page, figure/subplot, Mach/Re/AoA/roll/cant, transition, area/length/datum, measured vs estimated label and extraction bounds per series. Add A53D02/R-100 only where they broaden a specific declared geometry/regime. Do not fit all curves and call another point on the same curve independent qualification.
2. **Input/comparator packet:** use pinned, output-stripped RocketPaper inputs for a small number of development reconstructions. Resolve the L1395 designation and weather LFS object before promising reproducibility. Record powered/off CD provenance and normalization, nozzle assumptions, gravity/atmosphere/rail-event conventions and actual software/build pins. Independent code agreement is a software/numerical check.
3. **Public archive qualification:** provide the custodian the UND pinned tree and allowlisted NASA design paths. Request only an eligibility manifest and sanitized input package first. Custodian may inspect protected telemetry and original notes outside the development workspace; developers must not browse full reports/repository flight directories to fill gaps. Keep NASA and IREC design branches separate. If the archive does not document a required field, mark unknown instead of reverse-fitting it from altitude.
4. **Parallel-to-development acquisition task:** obtain permission for the minimal package below from at least two independent team/source families, selecting enough distinct as-flown vehicles for the final declared breadth. The historical proposal is six vehicles/two sources; it remains a proposal, not a newly approved or statistically sufficient universal gate. One complete vehicle package is the smallest useful ingestion pilot, but cannot close collegiate generalization. Agreement on access or a filename listing is not receipt of qualified data.

Use separate access-controlled **input** and **outcome** stores owned by a person/institution independent of model development and scoring choices. Custodian keeps original immutable files, hashes, rights record and mapping from pseudonyms to team/site/sensor IDs. Developers receive only the minimum physical inputs and their uncertainties; strip saved simulations, telemetry, residual plots, launch-report results and fitted parameters from mixed files. Location/time may be necessary physical inputs: keep privately with the authorized analyst rather than destroying accuracy through arbitrary rounding. Remove names/emails, radio IDs and unrelated payload details; do not put raw team files or confidential locations in Git. Store hashes/manifests and approved summaries only. Retention, permitted internal analysis, redistribution/publication, derivative coefficient rights and deletion/access responsibilities must be agreed with the owner.

Before release, the custodian establishes a frozen analysis-ready observation schema and uncertainty method without exposing outcome values. Freeze eligibility/exclusions, model/source/WASM hashes, settings, uncertainty model, domain, decision budgets, score definitions and every prediction artifact; timestamp/hash the package in custody. Only then release observations for scoring, or have the custodian run the frozen scorer and publish an independently auditable record. Record every exclusion/failure and all source/vehicle dependencies. Any tuning after release makes those examined outcomes development data for the modified model.

## Can old archived flights be genuinely held out?

**Yes, as retrospectively blinded external validation**, if no developer/model-selection participant has seen their outcomes or outcome-derived inputs, a custodian certifies the exposure boundary and as-flown provenance, cohort selection/exclusions are frozen independently of residuals, and predictions are committed before release. Existing public accessibility does not itself prove exposure, but it makes exposure control harder: prohibit browsing linked flight reports and maintain an explicit per-person/source exposure ledger. De-identification alone cannot erase prior knowledge.

This cannot recreate a historical **prospective preflight** prediction. If actual/reanalysis weather or reconstructed inputs are used, label the result conditional on those inputs. Parameters fitted to the archived flight disqualify that flight as blind for the fitted model; do not hide the fit in a drag table. Previously examined DOFPro/AltimeterCloud flights, published RASAero table entries, and RocketPaper summary-exposed validation cases remain development evidence. Reserved data remain reserved under their existing protocol and must not be repurposed by this plan.

## Exposure and closure decision

New exposure this research: NASA experimental coefficient/method reports; RocketPaper file metadata and README descriptions including event row anchors; UND repository root README/license/tree **filenames and sizes only**; two ENG motor inputs; NOAA and tool documentation. RocketPaper root also repeats its already exposed aggregate accuracy claim. No measured flight values, traces, apogees, landings or raw outcome channels were newly opened. Because the READMEs identify event locations and published validation context, all RocketPaper cases in this plan are explicitly development-only. UND flight values remain unexposed in this research; their suitability as a fresh archival holdout is pending independent qualification, not certified here.

**Decision:** start the bounded coefficient/input work with public material now; give the custodian a precise UND archive qualification task and the team request schema. Public data are not yet demonstrated sufficient for a primary collegiate accuracy claim across apogee, transonic native aero, rail departure, loads, recovery and dispersion. A qualified narrower claim may close earlier; absent measurements remain explicit unsupported outputs. No calendar promise should treat team permission, archive linkage or instrumentation uncertainty as already resolved.
