## 2. Target A — unconditional native URL/path logging

### 2.1 Defect (source-evidenced)

`src-tauri/src/lib.rs:18-32`: `log_download` always builds
`std::env::temp_dir()/astraea-download.log` and opens it with
`OpenOptions::new().create(true).append(true)` — no opt-in, no `O_NOFOLLOW`/
`O_EXCL`, no mode restriction, no size/rotation bound. The `on_download` callback
(`lib.rs:255-265`) passes the caller-formatted URL plus the full destination/path
(`format!("requested url={url} dest={destination:?}")`,
`format!("finished success={success} url={url} path={path:?}")`). On a shared
Linux temp dir this is a predictable, world-readable append target containing home
paths and export URLs; a pre-planted symlink redirects the append to any
user-writable file. Nothing reads the file in-repo except two manual
desktop-acceptance rows (`docs/internal/desktop-acceptance-checklist.md:214,245`)
and a diagnosis note. Existing `startup_trace` is the contrasting pattern: opt-in
`ASTRAEA_STARTUP_TRACE_OUT` and no URLs/paths.

### 2.2 Bounded failing-before reproduction (executed)

Disposable root `/tmp/rmp18-logrepro`; each case ran with `TMPDIR` pointing inside
that root, so the real `$HOME`/`/tmp` diagnostic path was never created (checked
absent). The exact 10-line function text was extracted mechanically from
`src-tauri/src/lib.rs:23-32` (sha256 `974ed8fa…0eed25b`, parent file
`fcdfd274…8b39c1`) and `include!`d into a rustc-only harness
(`rustc 1.99.1`, `--edition 2021 -O`). Not a Tauri build.

| Probe | Observed |
| --- | --- |
| predictable shared-temp file | created at `$TMPDIR/astraea-download.log`, mode `644`, 336 B after two callback messages; content is `[epoch-ms] requested url=… dest="/home/example-user/Downloads/…"` and `finished … path="/home/example-user/…"` |
| symlink follow | with a pre-existing symlink at that path pointing at a user-owned file, the two log lines were appended **into the victim** (`log_is_symlink=true`, victim 19 → 355 B) |
| no size bound | 2,000 calls produced 324,000 B; no cap/rotation observed |

Evidence (outside Git): `~/.paseo/worktrees/3s8t98rp/evidence-rmp18-rights-security/`
— `repro-privacy.log`, `repro-symlink.log`, `repro-growth.log`, `REPRO.json`,
`log_download_exact.rs`, `repro-harness.rs`, `hashes.txt`. Throwaway build and
temp roots removed after capture.

Honest limits: proves the exact function text follows symlinks and writes a
world-readable predictable file on Linux; it does not execute the packaged app,
WebView2/Windows temp semantics, a multi-user race, or a real user-file exploit.
No installed-Tauri acceptance follows.

### 2.3 Proposed correction (smallest maintainable: remove the dead sink)

- Delete `fn log_download` (`lib.rs:18-32`) and the now-unused imports
  `std::fs::OpenOptions`, `std::io::Write`, and `SystemTime`/`UNIX_EPOCH`
  (`use std::time::Duration;` stays).
- Replace the logging match with the equivalent control flow:
  `.on_download(|_webview, _event| true)` plus a comment that the handler allows
  every download and deliberately records no URL/path.
- Keep both `on_permission_request` `AutomaticDownloads => Allow` and the explicit
  handler: they are what make the second and later downloads work (desktop
  acceptance row 2.5). Return value for every event was already `true`; only the
  side effect disappears.
- No new dependency, capability, cache, destination policy, file, or CSP change.
  `src-tauri/capabilities/default.json` untouched.

Rejected alternatives:

- **Retained diagnostic**: would need an explicit opt-in env var (as
  `startup_trace`), a caller-supplied absolute path, event codes only (no URL or
  path), `create_new`/`O_NOFOLLOW`, `0600`, and a byte/line bound. More surface
  and permanent privacy risk for a historical debugging aid with no reader; not
  proposed unless the coordinator wants the capability back later.
- New logging framework/rotation: unwarranted abstraction.
- Narrowing the message fields only: leaves the predictable shared file and
  symlink-following append.

## 3. Target B — accompanying notices for the bundled surface

### 3.1 Mechanism

- Add generated, checked-in `public/third-party-notices.txt` (Vite copies it to
  `dist/`, Tauri embeds it). Plain text, no build step rewrites it at runtime.
- Add `scripts/third-party-notices.mjs` (plain Node, no new dependency, no
  network, no scanner service): reads the installed production closure via
  `pnpm list --prod --depth 20 --json`, skips `@types/*`, resolves each package's
  license field and license text file, deduplicates by exact text hash, and emits:
  1. first-party Apache-2.0 (root `LICENSE` text) — the distributed copy must
     carry it;
  2. the two font `LICENSE` files verbatim (copyright line + OFL-1.1 text);
  3. JS dependencies: full verbatim license text per distinct text, with the
     exact `name@version` + declared SPDX list that maps to it;
  4. WASM crates: all 21 non-workspace entries of
     `crates/astraea-engine/Cargo.lock` with verbatim texts from the local Cargo
     cache (a few are build-only, so this is a harmless superset);
  5. an explicit unresolved section: the 8 packages with no installed text, the
     undeclared-SPDX package (MIT text present), the desktop native closure, and
     the NASA CEA data terms.
- Estimated size ≈ 150–200 KB (72 distinct texts, ~142 KB before headers);
  deterministic order. Regeneration command documented in the file header; no CI
  wiring, no lock changes, no package changes.
- Access: landing footer link (`index.html`) and one app link in the
  `ModelStatusPanel` validation row. Relative targets (`./third-party-notices.txt`
  from `/`, `../third-party-notices.txt` from `/app/`) so subpath hosting and the
  Tauri custom protocol both resolve; no CSP change (`default-src 'self'` already
  permits it).

Decisions for coordinator: (a) approve a small generator script rather than a
hand-maintained 150 KB file (recommended: generator + committed output);
(b) whether the shipped file keeps the explicit unresolved section (recommended:
yes — truthful, no publication authority exists) or the gaps stay only in the
internal inventory; (c) SPDX choice `MIT OR GPL-3.0-or-later` for JSZip is MIT —
a license choice permitted by the package, not evidence of legal review.
